### S7 协议要点（踩坑，务必记住）

- **TPKT 长度字段含首部本身**：`03 00 LL LL` 的 LL 是整帧长度，不是剩余长度。
- **COTP PDU 类型在 frame[5]，不是 frame[1]**。frame[4]=LI、frame[5]=类型（E0=CR, D0=CC, F0=DT）。
  写错这个索引 → 连接永远失败（我第一版就踩了，自测才发现）。
- COTP CR 的 LI = 0x11（17），整帧 22 字节；目标 TSAP 第二字节 = 机架×32 + 槽位。
- **S7 头长度分两种**：Job = 10 字节；Ack/Ack_Data = 12 字节（多错误类+错误码）。
  参数区/数据区都从各自的 headerSize 之后开始，不能硬编码 10。
- **请求项的地址是位编址**：3 字节 = 字节地址×8 + 位偏移。DB10 字节 5 → `00 00 28`。
  BOOL 例外，地址字段直接就是位号。
- **请求项与数据区用两套不同的传输大小编码**：请求项 BOOL=01/BYTE=02/CHAR=03/WORD=04/INT=05/
  DWORD=06/DINT=07/REAL=08；数据区 NULL=03/BYTE-WORD-DWORD=04/INT=05/DINT=06/REAL=07/OCTET=09。
  写错必然被 PLC 拒。
- **数据区的长度单位随传输大小变**：0x03/0x04 以「位」计，其余以「字节」计。
- 写应答（0x05）的数据区**只有一个返回码字节**，没有数据项，
  所以不能复用 `ParseReadItems`（否则报「无数据」）。
- S7 走 TCP 102 且报文带长度字段，**追加 `\r\n` 会让 PLC 直接丢帧**：
  `BuildSendPayload` 里按 `IsS7Tab` 屏蔽，并在 S7 页签隐藏该复选框、改显示提示文字。

### 自测方法（--s7test，比 --dualtest 多两个坑）

1. **握手是同步阻塞的，必须放后台线程**。`S7Transport.Open()` 内部有带超时的同步读，
   在 UI 线程直接调用会和消息泵互锁，整个进程挂住不产出报告。
2. **VM 仍必须在 UI 线程构造**（DispatcherTimer 绑定 `Dispatcher.CurrentDispatcher`），
   所以是「UI 线程建 VM → `Task.Run` 跑逻辑」。
3. `ShowWarning` 是 MessageBox 模态，后台线程调用会卡死等点击。自测里只走成功路径，
   或故意失败时确保不会弹窗。
4. 模拟 PLC（FakePlc）+ echo（EchoServer）都要在 try 外 new，才能在收尾统一 Stop。
5. 自测会写脏 settings.json（Network.Mode、SendHistory），跑完要手工恢复。
6. 终端读 UTF-8 报告需 `-Encoding UTF8`，否则中文乱码。

自测已删除（App.xaml.cs 回到干净版 + FakePlc.cs / EchoServer.cs / S7TestWindow.cs 已删）。

## Bugfix：HEX 报文多行只显示首行

**现象**：超过 16 字节的报文，`接收 N 字节：` 后面的 HEX 换行处断行异常，
第二行内容缺失或挤在一起（截图里 11 字节报文的第一行正常、后续字节跑到框外）。

**根因**：`HexConverter.ToHexLines` 每 16 字节插一个 `\r\n`，而
`MainWindow.OnLogAppended` 把整段多行字符串塞进**一个** `Run`。
WPF 的 FlowDocument 里 `Run.Text` 的换行符不会产生真正的换行——
`Run` 只是纯文本载体，断行必须由多个 `Paragraph` 表达。

**修法**：`OnLogAppended` 里把 content 按 `\r\n`/`\n` 拆成多行，
每行建一个独立 `Paragraph`；只有第一行加 prefix（时间戳+字节数），续行留空前缀以便左对齐。

**连带影响（都无需额外改动）**：
- `TrimDocument` 现在按**视觉行**而非逻辑条目裁剪，`MaxLogLines=5000` 含义变为 5000 行，可接受。
- `OnThemeChanged` 的 `runs.Count >= 2` 判断天然兼容：首行 2 个 Run（前缀+正文），
  续行 1 个 Run 直接刷正文色。

**教训**：WPF 里凡是「多行文本」都不能靠 Run 里的 `\n`，要么拆 Paragraph，要么用 `LineBreak`。
`BlockCollection` 不能用 `[]` 索引，要 `.Cast<Block>().ToList()`。

自测方式：`--logtest` 分支用反射调 `AppendLog` 灌 40 字节，检查 `LogBox.Document.Blocks.Count`
是否等于 `ToHexLines` 的行数（验证为 3 == 3）。已删除。

## Bugfix：日志区右侧大块空白 + 多余横向滚动条

**现象**：不勾「自动换行」时，日志行右侧永远拖着一大截空白，底部还有条横向滚动条。

**根因**：`ApplyWordWrap` 里不换行分支写死 `PageWidth = 20000`（20 像素×1000）。
FlowDocument 只能靠 PageWidth 模拟换行行为，页宽一旦写死，文档就被撑到可视区右侧很远。

**修法**：改成按内容实测宽度动态设置——`UpdatePageWidthToContent()`：
- 用 `FormattedText`（dpi 取 `VisualTreeHelper.GetDpi(LogBox).PixelsPerDip`）量每行宽度；
- `_widestLineWidth` 缓存最大值，追加时用 `NoteLineWidth()` **增量**更新，
  **不要每条日志全量遍历**（高频收包会明显拖慢渲染）；
- `PageWidth = Math.Max(内容宽 + PagePadding + 4, 可视宽)`；
  内容放得下就收窄到可视宽（空白消失），放不下才撑开触发滚动条。
- 全量 `recompute: true` 的时机：字号变化、从换行切回不换行。
  清空日志时置 0。窗口 `SizeChanged` 时重贴页宽（可视宽变了）。

**结果**：短内容 PageWidth=1138.7（贴合可视宽）、400 字符单行=3026.6（撑开）、
自动换行=NaN、关掉换行=3026.6（缓存生效）。

**WPF 坑**：
- `FontFamily` 没有 `ToTypeface()`；用 `document.FontFamily.GetTypefaces().FirstOrDefault()`。
- `BlockCollection` 不支持 `[]`，要 `.Cast<Block>().ToList()`。
- `HorizontalScrollBarVisibility = Auto` 配合「页宽贴合内容」，
  滚动条就只在真正超宽时出现，无需手动隐藏。
