# 2026-10-22

## 新增 MQTT 页签（第 4 个通道）

**成果**：`MQTT` 页签，与串口 / TCP·UDP / S7 四条连接可同时保持。

### 结构
- `Services/ITopicTransport.cs`：`ITopicTransport : ITransport`，加 `TopicMessageReceived` 事件与 `Publish(topic,payload,qos,retain)`。
  `TopicMessage` 带 Topic / Payload / Qos / Retain。
- `Models/MqttSettings.cs`：Host/Port/ClientId/UserName/Password/UseTls/CleanSession/ProtocolVersion/KeepAlive/
  PublishTopic/SubscribeTopic/PublishQos/SubscribeQos/Retain/AutoReconnect + `Clone()`。
- `Services/MqttTransport.cs`：MQTTnet 5.2.0.1603。
- `LogChannel.MQTT = 3`；日志按通道隔离，MQTT 消息按主题分条显示（前缀含主题 / QoS / 保留位）。

### MQTTnet 5 API 要点（踩坑记录）
- 所有类型都在根命名空间 `MQTTnet`（没有 `MQTTnet.Client`）；`MqttClientFactory` 建客户端。
- 事件签名是 `Func<T, Task>`，接收事件里必须返回 `Task.CompletedTask`。
- `Payload` 是 `ReadOnlySequence<byte>`，取数组要 `.ToArray()`。
- 凭据用 `builder.WithCredentials(user, Encoding.UTF8.GetBytes(pwd))`；`MqttClientCredentials` 只有带参构造、无属性。
- TLS 用 **builder DSL**：`builder.WithTlsOptions(t => t.UseTls().WithTargetHost(h).WithAllowUntrustedCertificates(true)...)`，
  不是给 options 对象赋属性。
- 订阅：`MqttClientSubscribeOptionsBuilder().WithTopicFilter(topic, qos)`。
- QoS 是枚举 `MqttQualityOfServiceLevel`，接口里的 `Publish` 用 int，需要强转。

### 刻意设计
- `MqttTransport.DataReceived` 用空 add/remove 实现（不投递），避免同一条消息被记两遍；
  接收一律走 `TopicMessageReceived`。
- `ClientId` 在构造函数里就定下来，`Description` 才能在连接前带上它。
- QoS 在设置里存的是「0 最多一次」这类标签，解析要取前面数字（`ParseQosText`）。

## 修掉两个隐藏的越界崩溃（自测发现，非 MQTT 独有）
- `MainWindow.xaml.cs`：`_documents` / `_widestLineWidths` 长度 3 → **必须 4**，
  否则点 MQTT 页签时 `SwitchChannel()` 抛 `IndexOutOfRangeException`。
- `MainViewModel.cs`：`_logLines` 队列数组 `[new(), new(), new()]` → **必须 4**，否则 MQTT 写日志越界。
- `OpenTransport` 的 `switch (slot)` 缺 `case 3`，MQTT 会落进 `default` 被塞进 `_serialTransport`（顶掉串口连接）。

> 教训：**每加一个通道，凡是 `new T[n]` 的地方都要同步 +1**。这类数组不会编译报错，只在切页签/写日志时炸。

## 验证方法（本地无 broker 时）
- 临时用 `MQTTnet.Server` 在 1884 起一个 broker（独立 console 项目），主程序加 `--mqtt-selftest` 分支跑断言，完事删除。
- 关键断言点：页签数=4、IsMqttTab、订阅回显、发布后再收回来（broker 会把消息回送给同客户端）、
  Rx/Tx 字节数、日志里出现「主题 uart/rx」。
- WPF 自测注意：`window.DataContext`、`window.MainTabs` 都是 DependencyObject 属性，
  **必须在 Dispatcher 里读**，否则跨线程异常。

## 参数区控件统一单行（宽度预算）
- 顶部参数区是 WrapPanel，宽度超了就会折成两行。**窗口默认宽 1180 → 1290**，
  各页签控件同时收窄，实测（默认宽度下）：

  | 区域 | 可用宽 | 需要宽 | 结果 |
  |---|---|---|---|
  | 串口 | 1025 | 973 | 单行 |
  | TCP·UDP | 1025 | 408 | 单行 |
  | S7 | 1025 | 501 | 单行 |
  | MQTT | 1025 | 953 | 单行 |
  | MQTT 主题区 | 1225 | 1107 | 单行 |

- 收窄后的宽度：串口 86 / 波特率 90 / 数据位 56 / 校验 84 / 停止位 72 / 流控 118 / 编码 80；
  MQTT 客户端 ID 104、用户名与密码 78、订阅主题 140。
- 窗口 MinWidth 仍是 900，**用户手动拖窄到约 1090 以下**时参数区会折行（WrapPanel 的固有行为），
  默认尺寸下不会。
- 量法：临时 `--layout-check` 分支，逐页签 `UpdateLayout()` 后取 WrapPanel 的
  `ActualWidth` 与子元素 `DesiredSize.Width` 之和比较，`DesiredSize.Height / 单行高` 即行数。
  `DesiredSize` 已含 Margin，直接求和即可。验证完删除。

## 新增 OPC UA 页签（第 5 个通道，含客户端 + 服务端）

**成果**：`OPC UA` 页签，方式可切「客户端 / 服务端」，与其余四条连接并存。

### 依赖
- `OPCFoundation.NetStandard.Opc.Ua.Client` + `...Server`，**版本必须钉 1.5.374.78**。
  1.5.375+ / 2.0.x 做了异步重构：`CoreClientUtils` 消失、`ApplicationInstance.CheckApplicationInstanceCertificate`
  改异步、`Session.Create` 签名全变，网上文档又还是老 API，编译满地错。1.5.374.78 有 net8.0 目标，能跑在 net9 上。
- 打包体积从 65MB → 71MB。

### 结构
- `Services/OpcUaConfig.cs`：拼 `ApplicationConfiguration`。证书在 `%APPDATA%\WPF-UartAssist\pki`，
  首次启动自动生成自签名证书（约 1 秒）。`AutoAcceptUntrustedCertificates = true`。
- `Services/OpcUaServerHost.cs`：`StandardServer` + `CustomNodeManager2` 起内置服务端，
  演示地址空间 `Objects/Demo/{Text,Counter,Enabled,Temperature}`，SecurityPolicy=None + 匿名。
  命名空间索引实测 **ns=2**（`DemoNodeManager.NamespaceIndex`）。
- `Services/OpcUaClientTransport.cs`：实现 `ITransport`，`Open/Close/ReadNode/WriteNode/BrowseObjects`。
  `Send()` 直接抛 NotSupported（OPC UA 没有字节流概念）；`DataReceived` 与 `ErrorOccurred` 用空 add/remove。
  统计里把「读到的值字节数 / 写入值字节数」当收/发字节。
- `ViewModels/OpcUaVariableRow.cs`：服务端变量在界面上的行。

### OPC UA 1.5.374 关键 API（踩坑后确认）
- `using Opc.Ua; using Opc.Ua.Configuration; using Opc.Ua.Server;`
- `CoreClientUtils` 在 **`Opc.Ua.Client`** 命名空间，不是 `Opc.Ua`。
- `Session` 有歧义，要写全 `Opc.Ua.Client.Session`。
- `await Session.Create(config, endpoint, false, sessionName, 60000u, identity, null)` —— 返回 **Task<Session>**。
- 读：`session.Read(null, 0, TimestampsToReturn.Both, toRead, out DataValueCollection results, out DiagnosticInfoCollection diags)`
- 写：`session.Write(null, toWrite, out StatusCodeCollection results, out ...)`
- 服务端：`app.CheckApplicationInstanceCertificate(true, 0)`、`app.Start(server)`、`app.Stop()`。
- `ServerConfiguration.BaseAddresses` 是 **`Opc.Ua.StringCollection`**；`UserIdentity(user, password)` 两个都是 string。

### 致命坑：UI 线程调用会卡死
OPC UA 栈内部有同步等待，直接在 UI 线程 `server.Start()` / `Session.Create()` 会**永久阻塞**
（现象：点按钮后界面无响应、排查时误以为是自定义代码死循环）。
所有建链/启停/读写一律 `Task.Run(...).GetAwaiter().GetResult()` 包一层。服务层直连（后台线程）本来就是好的，
正是这个对比才定位到问题。

### 又是数组越界（第 5 个通道）
`MainViewModel._logLines` 仍是 `[new(), new(), new(), new()]`（4 个），OPC UA 写日志时
`AppendEntry` 抛 `IndexOutOfRangeException`，被 `StartOpcUaServer` 的 catch 转成「服务端启动失败」弹窗。
`_rxLinesPerChannel` 已改 5，`_documents`/`_widestLineHeights` 已改 5，**唯独漏了这个**。

> 再次确认：加通道时把所有 `new T[n]` 搜一遍（`grep "new .*\[[0-9]\]"`），别只看自己记得的那几个。

### 界面
- 页签行：方式下拉 + 客户端（端点/用户名登录/用户名/密码）或服务端（监听端口 + 状态文字）+ 连接|断开 或 启动服务端|停止。
- 面板（Grid.Row=6）按方式切换两套内容：
  客户端 NodeId 读取/浏览/写入 + 结果行；服务端 变量下拉改值 + 变量卡片列表。
- OPC UA 不是字节流，**该页签下把发送区整块隐藏**（`IsOpcUaTab` 取反）。
- 主 Grid 行数 8 → 9（发送区 7、状态栏 8）。

### 验证
临时 `--opcua-selftest` 跑通：服务端启动（4 变量 ns=2）→ 本地改 Counter=77 → 客户端连本机端点 →
读 Text='hello opc ua' → 写 '123' → 读回 123 → 浏览到 `ns=2;s=Demo` → 断开/停止。

## 修复：连接 OPC UA 服务端报 BadSecureChannelClosed

**根因**：用户机器上 4840 端口被 `opcualds.exe`（OPC UA 本地发现服务，Windows 服务）监听。
LDS 只受理 GetEndpoints 发现，不建会话——客户端能完成 discovery，一 CreateSession 就被掐断，
报 `BadSecureChannelClosed`。

**更阴险的发现**：LDS 占着 0.0.0.0:4840 时，我们的服务端用套接字复用**仍然能绑定 4840 "成功"**，
连接会随机落到 LDS 或我们这边。所以「服务端看起来启动成功」不代表端口没被占。

**修复**（三处）：
1. `OpcUaSettings` 默认端口/端点 4840 → **48400**（新装用户不再撞 LDS；老用户的 settings.json 里存的旧值需手动改）。
2. 客户端连接失败信息翻译：`BadSecureChannelClosed` 等追加「可能是 LDS / 安全策略不匹配 / 对方拒绝」三条原因。
3. **服务端启动前先查 `IPGlobalProperties.GetActiveTcpListeners()`**，端口已被监听直接拒绝并提示换端口。
   不要指望 bind 失败——套接字复用会让它"成功"。

**测试基建**：`MainViewModel.SuppressDialogs`（internal static）+ `LastDialogTitle/LastDialogMessage`，
自测时静默 MessageBox 并抓取文案。没有这个，自测会在 ShowWarning 的模态框上永远卡住——
之前几次「报告未生成/进程挂住」其实都是弹窗在等确认。

## TCP/UDP 页签支持 Modbus TCP

Modbus 构造器原来只在串口页签、只出 RTU（带 CRC16）。现在扩展成 RTU / TCP 双格式。

- `Services/ModbusRtu.cs`：拆出 `BuildPdu(function, address, quantity, writeData)`（功能码+地址+数量/数据，两种帧共用），
  新增 `BuildTcpRequest(transactionId, unitId, pdu)` = MBAP(7) + PDU，无 CRC；
  `BuildRequest` 改为 `unit + PDU + CRC16`，行为不变。
- `ModbusRtuViewModel`：加 `FrameModes`（Modbus RTU / Modbus TCP）、`SelectedFrameMode`、`IsTcpFrame`、
  `TransactionIdText`（发送后自动 +1）、`CheckboxText`、`FrameNote`、`UnitLabel`（TCP 下叫单元号）。
  从站号校验按格式区分：RTU 1–247，TCP 0–255。
- `MainViewModel`：`SupportsModbusTab = IsSerialTab || IsNetworkTab`；切页签时**帧格式跟着自动切**
  （串口→RTU，网络→TCP，用户仍可手动改）；只有非串口非网络的页签才自动收起面板。
- 界面：勾选框文字随格式变化；面板加「帧格式」下拉与「事务号」输入（仅 TCP 显示），底部说明也随格式切换。

**验证**（临时 `--modbus-probe`）：
- RTU `01 03 00 00 00 01 84 0A`（数量默认 1，CRC 正确）
- TCP `00 01 00 00 00 06 01 03 00 00 00 01`
- 改事务号 0x1234 / 地址 0x0010 / 数量 2 → `12 34 00 00 00 06 01 03 00 10 00 02`
- 真实发送：本地 TcpListener 收到完全相同的 12 字节；发送后事务号 0x1234 → 0x1235（4661）
- 切到 S7 页签 Modbus 面板自动收起
